# King-coffee 텀블러 A/B 테스트 시뮬레이터 — 데이터 분석 포트폴리오

King-coffee(치킨과 커피를 함께 파는 매장) 2주년 기념 무료 증정 텀블러 디자인에 대한 고객
반응을 파악하기 위해, 가상의 투표 페이지를 만들고 Claude API로 페르소나별 행동을 시뮬레이션해
"AI 네이티브" 행동 로그 데이터를 생성하고, 그 데이터를 통계적으로 분석한 프로젝트입니다.

이 저장소에는 전체 코드베이스 중 **데이터 분석 파이프라인 2개(`pilot/pilot_analysis.py`,
`main/main_analysis.py`)와 이 설명 문서만** 포트폴리오용으로 공개되어 있습니다. 웹 서버(Flask),
Claude API 봇, DB 연결 모듈 등 실행 인프라 코드는 포함되어 있지 않아 이 저장소만으로 바로
재현 실행은 되지 않습니다 — 데이터가 어떤 경로로 만들어졌고, 그 데이터를 어떤 방식으로
분석했는지를 보여주는 것이 목적입니다.

---

## 1. 프로젝트 개요

- **목표**: 실제 설문 없이도 현실적인 소비자 행동 패턴(연령대/유입채널/시간대별 반응 차이,
  이탈률, 체류시간-선택 상관관계, A안/B안 간 전환율 차이 등)이 담긴 로그 데이터를 만들어낸다.
- **핵심 아이디어**: 단순 랜덤이 아니라, Claude에게 각 페르소나의 입장에서 "이 사람이라면
  어떻게 행동할까?"를 직접 판단하게 해서 데이터에 실제 소비자 심리에 가까운 패턴이 생기도록 한다.
- **대상 상품**: King-coffee 2주년 기념 무료 증정 텀블러 2종 — 방문자는 둘 중 무작위로
  배정된 **하나만** 본다 (대조군/실험군 구조)
  - **A안**: 원형 이중 테두리 안에 브랜드 캐릭터(여자아이+커피잔 실루엣)만. 상호명 없음. 심플·미니멀.
  - **B안**: 하트형 이중 테두리 안에 캐릭터. 테두리를 따라 'KING-COFFEE' + '2nd Anniversary' 텍스트. 감성적·따뜻함.

## 2. 데이터셋은 어떻게 만들어졌나

### 시스템 구조 (참고용 — 아래 인프라 코드는 이 저장소에 미포함)

```
[브라우저] ←→ [Flask 서버 app.py] ←→ [SQLite visit_log]
                                              ↑
                    [bot.py] ──Claude API──→ 행동 결정 → POST /log
```

가상 방문자(페르소나) 한 명이 생성될 때마다 `bot.py`가 연령대·성별·유입채널·방문시간대를
무작위로 부여하고, A안 또는 B안 중 하나에 배정한 뒤 Claude에게 "이 페르소나라면 이 디자인을
보고 어떻게 행동할까?"를 판단하게 한다. 그 결과(조회 여부·위시리스트·최종 선택·체류시간·선택
이유)가 `visit_log` 테이블에 한 행씩 쌓인다.

`visit_log` 컬럼: `user_id, age_group, gender, channel, time_slot, group_name(A/B), viewed,
time_on, wishlist, selected, session_sec, reason, timestamp` — 방문자 1명 = 1행.

### 두 단계 실험 설계 — pilot → main

1. **파일럿 단계**: A안만 단독으로 노출해 베이스라인 선택률을 먼저 잰다
   (`pilot/pilot_analysis.py`가 이 데이터로 EDA + 필요 표본수 계산 수행).
2. **본실험 단계**: 파일럿에서 얻은 베이스라인·표본수를 근거로, A/B를 50:50 무작위 배정해
   본실험을 돌린다 (`main/main_analysis.py`가 이 데이터를 검증·분석).

## 3. 페르소나 행동 시뮬레이션 방법론

`bot.py`가 Claude를 호출할 때마다 아래 기준을 방향성으로 제시하고, 정확한 확률은 숫자로
못박지 않은 채 Claude가 페르소나 조합(연령대×성별×채널×시간대)마다 매번 유연하게 해석하도록
설계했다 — 그래서 실행할 때마다 결과가 자연스럽게 조금씩 달라진다(의도된 설계).

- **연령대**: 10-20대는 트렌디·SNS 공유 성향, 30-40대는 실용성·브랜드 신뢰도 함께 고려,
  50대 이상은 실용 정보 선호·결정까지 시간 소요.
- **유입채널**: SNS는 감성적 트리거에 민감, direct(매장 방문 후 QR)는 이미 신뢰가 있는
  상태, friend_share는 사회적 증거에 영향, search는 목적의식이 뚜렷해 이탈률 낮음.
- **시간대**: 아침/점심은 빠른 결정, 오후/저녁은 여유, 심야는 이탈률 다소 상승.
- **이탈 처리**: 모든 페르소나가 반드시 선택하는 게 아니라, 살펴보지 않거나 마음에 안 들어
  이탈하는 경우도 현실적으로 반영.
- **균형 유지 원칙**: 위 경향성은 참고용 방향성일 뿐, 특정 안이 구조적으로 항상 우세하도록
  설계하지 않았다 — 대량 실행 시 A/B 어느 쪽도 선택률 0%로 수렴해서는 안 된다는 원칙을
  세우고, 위에서 언급한 앵커링 버그를 이 원칙에 따라 발견·수정했다.

## 4. 분석 파이프라인 (이 저장소에 포함된 코드)

### `pilot/pilot_analysis.py` — 파일럿 EDA + 본실험 표본수/검정력 분석

파일럿(A안 단독 노출) 로그를 읽어 다음을 순서대로 수행한다.

1. **EDA** — 세그먼트(연령대/성별/유입채널/시간대)별 선택률을 살펴보고, 베이스라인이
   특정 세그먼트에 치우쳐 있지 않은지 확인.
2. **베이스라인 산출** — 전체 선택률을 본실험 표본수 계산의 입력값(p1)으로 사용.
3. **표본수 계산** — 두 비율 z-검정 공식으로, "본실험에서 이 정도 차이(MDE)는 반드시
   탐지하고 싶다"는 목표를 넣으면 군당 필요한 최소 표본수를 역산.
4. **검정력 곡선** — 표본수를 늘려갈수록 검정력이 어떻게 올라가는지 MDE별로 시각화.

### `main/main_analysis.py` — 본실험(A/B) 통합 분석 파이프라인

본실험(A/B 50:50 무작위 배정) 로그를 6단계로 검증·분석한다.

1. **SRM 게이트** — 배정 비율 자체가 의도한 50:50대로 이루어졌는지부터 확인. 카이제곱
   적합도 검정을 `math.erfc` 수동 구현과 `scipy` 양쪽으로 교차 검증.
2. **공변량 균형 게이트** — 연령대·성별·채널·시간대 구성비가 A/B 간에 쏠려 있지 않은지
   카이제곱 독립성 검정으로 확인 (배정 절차 자체의 편향 여부를 검증 — 결과 해석 이전의 게이트).
3. **EDA 요약 + 시각화** — 군별 방문자 수·전환율, 세그먼트 crosstab, 체류시간, 찜→선택
   전환율을 텍스트로 요약하고, 세그먼트별 A/B **선택률**을 막대그래프로 비교 시각화(인원수
   기준 crosstab만 보면 군별 전체 선택률 차이로 인한 착시가 생길 수 있어 비율 기준으로 보완).
4. **두 비율 z-검정** — A/B 선택률 차이가 우연이 아닌지 검정하고, 카이제곱 독립성 검정으로
   교차 검증(z² == chi²). A/B 선택률을 95% 신뢰구간과 함께 막대그래프로 시각화.
5. **효과크기** — Cohen's h, 상대위험도, 오즈비, 파이 계수로 "차이가 얼마나 큰가"를 판단.
6. **CSV 추출** — 분석용 원본 로그를 CSV로 저장.

두 파일 모두, SRM/공변량 균형처럼 **결과를 믿기 전에 먼저 통과해야 하는 검증 단계를
통계 검정 앞에 배치**한 것이 설계의 핵심이다 — 무작위 배정이 실제로 의도대로 이루어졌다는
근거 없이 곧장 A/B 차이를 해석하지 않도록 하기 위함.

  유의성 확인)

- 체류 시간(time_on)이 선택과 상관관계 있는가?
- 이탈(viewed=false 또는 selected=false) 고객의 특성은?
